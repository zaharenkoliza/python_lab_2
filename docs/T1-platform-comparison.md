# T1. Сравнительный анализ платформ автономных агентов

**Дата среза:** 19 октября 2026 года. **Сценарий выбора:** веб-инженер-исследователь собирает сведения из интернета, проверяет их браузером и скриптами, обрабатывает документы, а часть работы выполняет по расписанию. Практическая часть проекта ограничена P1: автономный Telegram-агент на VPS с постоянной памятью, навыком `arxiv-digest`, cron и восстановлением после перезагрузки. [Локальная постановка P1](p1-evidence.md).

Сравниваются Hermes Agent, OpenClaw, PicoClaw и ZeroClaw. «Встроено» означает функцию ядра или штатного поставляемого компонента; «через интеграцию» означает дополнительный пакет, MCP-сервер, внешний сервис или собственный скрипт. Возможность получить результат через shell сама по себе не равна готовому инструменту для PDF, браузера или видео. Источники ниже — документация и репозитории разработчиков; сравнительные оценки в разделе выбора являются моими выводами, а не официальными рейтингами.

## 4. Веса для веб-инженера-исследователя

Вес отражает цену провала конкретного вида работы. Для исследования пропуск динамической страницы, неверное извлечение PDF или невоспроизводимый эксперимент существеннее, чем разница в RAM между агентами на обычном VPS. При постоянной работе без присмотра растёт вес сохранения состояния, журналов и ограничения прав.

| Группа и критерий | Вес | Почему |
|---|---:|---|
| Архитектура: ресурсы и зависимость от среды | 12% | Определяет цену и возможность запуска на нужном VPS/edge. |
| Архитектура: размещение, подсистемы и восстановление после reboot | 13% | В P1 агент обязан продолжать работу без открытого Telegram и ручного перезапуска. |
| Исследование: поиск, чтение и JS-браузер | 15% | Без доступа к динамическим и авторизованным источникам корпус данных неполон. |
| Исследование: файлы и воспроизводимые вычисления | 10% | Нужны скрипты, сохранённые исходные данные и повторяемые результаты. |
| Исследование: PDF, таблицы, аудио/видео | 10% | Частые форматы первичных источников; важно отличать штатное извлечение от внешнего OCR/STT. |
| Исследование: навыки, MCP и свои инструменты | 8% | Позволяет добавить arXiv API и собственный метод сбора без смены платформы. |
| Исследование: сессии и делегирование | 7% | Ускоряет независимый сбор и сверку, но не заменяет проверку источников. |
| Эксплуатация: независимость от LLM-поставщика | 6% | Снижает риск недоступности модели и позволяет менять стоимость/качество. |
| Эксплуатация: логи, трассы и затраты | 6% | Нужны доказательства P1, диагностика и контроль бюджета. |
| Эксплуатация: права и изоляция | 8% | Бот с shell-доступом находится на постоянно включённом сервере. |
| Эксплуатация: зрелость и документация | 5% | Уменьшает риск застрять на настройке и поиске готового навыка. |
| **Итого** | **100%** | Архитектура 25%, исследование 50%, эксплуатация 25%. |

Веса — оценка задач, а не измеренный рейтинг платформ. Перед реальным развёртыванием проверяются стоп-условия: Telegram-канал, запрет посторонним, cron без клиента, постоянная память и автоматический старт. Платформа, не прошедшая хотя бы одно из них в выбранной конфигурации, не годится для P1 независимо от суммы баллов.

## 5. Выбор для P1 и условия пересмотра

**Для P1 выбирается Hermes Agent.** В проекте уже подготовлены [Docker Compose для шлюза и постоянного тома](../compose.yaml), [мастер настройки Telegram и модели](../scripts/03-setup-agent.sh), навык [`arxiv-digest`](../skills/arxiv-digest/SKILL.md), инструкции и [чек-лист проверки](p1-evidence.md). Hermes штатно сочетает Gateway, память, cron, навыки и наблюдаемость. Это напрямую покрывает критерии P1: доставка по расписанию при закрытом клиенте, сохранение данных и восстановление после reboot. Переключение на другую платформу добавит перенос конфига и повторную проверку без установленной выгоды для данного VPS.

Решение меняется при следующих условиях:

| Новое условие | Предпочтительный вариант | Причина |
|---|---|---|
| Большая доля задач — сложная работа в авторизованном браузере и нужен максимальный каталог готовых интеграций | OpenClaw | Развитые профили браузера, расширение и крупная экосистема. |
| Устройство имеет десятки МБ RAM, исследование ограничено простыми API/страницами, тяжёлые задачи вынесены вовне | PicoClaw | Очень малый runtime и быстрый старт; Chromium/OCR/STT всё равно потребуют отдельного узла. |
| Нужен однобинарный сервис на слабом устройстве при более строгих политиках исполнения | ZeroClaw | Rust-runtime, службы ОС, политики инструментов; документный конвейер потребуется собрать. |
| Нужны точные финансовые отчёты или гарантии для конкретного провайдера | Любая из платформ после пилота | Локальные оценки стоимости сверяются с биллингом LLM-провайдера; по документации нельзя обещать точный счёт. |

**Проверка решения по P1:** `docker compose up -d` и успешный диалог с разрешённого Telegram ID; отказ постороннему; чтение факта только из `USER.md`/`MEMORY.md`; минимум три запуска `arxiv-digest` по cron при закрытом Telegram; фиксация времени и токенов; `sudo reboot` и появление контейнера без ручного запуска. Команды и доказательства заданы в [чек-листе P1](p1-evidence.md). Эта проверка ещё должна быть выполнена на VPS: матрица сравнивает возможности, но не подменяет результат эксперимента.
