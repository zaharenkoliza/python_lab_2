# Журнал отладки (минимум 3 реальные ошибки — заполнять по ходу)
| # | Текст ошибки | Гипотеза | Проверка | Решение |
|---|---|---|---|---|
| 1 | `[Telegram] Connect attempt 1/8 failed: Timed out`, `gateway.run: ✗ telegram error: telegram connect timed out after 45s` | Telegram недоступен из сети или контейнера | `curl https://api.telegram.org/` из ВМ и из контейнера вернул 302 за 0,3 с, DNS резолвится в 149.154.166.110. Значит, сеть в порядке, а таймаут вызван первичным обнаружением fallback-адресов через DNS-over-HTTPS | Исправлять не потребовалось: шлюз сам переподключился через ~30 с (`Auto-discovered Telegram fallback IPs`, `Connected to Telegram (polling mode)`). Вывод: после первого старта подождать минуту, прежде чем искать неисправность |
| 2 | `ERROR agent.conversation_loop: API call failed after 3 retries. HTTP 429: Provider returned error \| provider=openrouter model=google/gemma-4-31b-it:free`; в Telegram: «the AI model service was rate-limited … No backup provider is configured» | Общий пул бесплатных (`:free`) моделей OpenRouter перегружен | Ручной запуск `hermes cron run` дал ту же ошибку (запись в `cron runs`: `failed`, `duration_ms=11649`, токенов нет); при этом сеть и ключ в порядке (`/api/v1/models` отвечает 200) | Добавлена цепочка резервных моделей `fallback_providers` (gemma-4-26b-a4b-it:free и nemotron-3.5-super-vl:free), контейнер перезапущен. После этого три плановых прогона прошли без ошибок. Оговорка: повторный успех мог быть связан и с падением нагрузки на провайдере, так что эффект fallback отдельно не доказан |
| 3 | Не ошибка выполнения, а дефект качества: в дайджесте прогона 1 (`docs/logs/cron/run-2026-10-29_14-53-26.md`, строка 59) «фреймворк自我эволюции», то есть китайские иероглифы внутри русского слова | Слабая бесплатная модель смешивает языки при генерации | `grep -P` по иероглифам во всех трёх выводах: найдено одно вхождение, в прогонах 2 и 3 нет | Исправление в навыке не вносилось: в навык можно добавить требование проверять вывод на посторонние символы, но на трёх прогонах это не подтверждено. Для отчёта это пример того, почему результат агента нужно проверять человеком |
Типичные кандидаты: `0 total bundled` / `No messaging platforms enabled` (неверная точка монтирования), HTTP 429 на `:free` модели, `Auxiliary title generation failed`.
